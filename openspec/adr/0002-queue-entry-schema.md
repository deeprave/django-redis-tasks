# ADR 0002: Queue Entry Schema and Payload Encoding

## Status

Proposed — subject to revision as the generic worker API is designed.

## Context

The generic queue layer needs a durable representation for a queued item that
can be identified, dispatched by asynchronous workers, inspected by callers,
and adapted to Django task results. Entries must be safe to exchange through a
shared Redis instance and portable across independent Python processes.

Although Python pickle would accept arbitrary Python objects, unpickling a value
from Redis can execute arbitrary code. A shared queue is therefore not a safe
pickle boundary, even when all intended producers are application services.

## Decision

The default queue-entry wire format is a JSON object. The queue accepts any
JSON-serializable value as `payload`; it is not restricted to dictionaries. The
caller is responsible for supplying a value that survives a JSON
serialization/deserialization round trip.

The in-process representation is a frozen, slotted `QueueEntry` dataclass. It
is converted to and from the JSON-object wire format at storage boundaries.
Mutations are represented as explicit replacement entries, rather than changing
an entry in place. Implementations must defensively copy mutable payloads and
results at API boundaries.

The durable schema is initially:

```json
{
  "id": "018f...",
  "queue": "default",
  "status": "queued",
  "queued_at": "2026-08-06T00:00:00.000000Z",
  "dispatched_at": null,
  "finished_at": null,
  "payload": null,
  "result": null,
  "error": null
}
```

Field requirements:

| Field | Requirement |
| --- | --- |
| `id` | A canonical UUID version 7 string generated by the queue. `enqueue()` returns this identifier. |
| `queue` | The named queue namespace. |
| `status` | One of `queued`, `running`, `succeeded`, or `failed`. |
| `queued_at` | A required UTC RFC 3339 timestamp set by the queue clock. |
| `dispatched_at` | `null` until dispatch begins, then a UTC queue-clock timestamp. |
| `finished_at` | `null` until handling completes, then a UTC queue-clock timestamp. |
| `payload` | Any JSON-serializable value supplied by the caller. |
| `result` | `null` until successful handling, then any JSON-serializable value returned by the handler. |
| `error` | `null` unless handling fails, then a JSON-serializable structured error object. |

For Redis-backed queues, every lifecycle timestamp uses the Redis-aligned clock
defined in ADR 0001. The value is obtained from cached Redis time plus elapsed
local monotonic time; it does not use the worker wall clock directly.

The default API does not support pickle. A future specialized codec may be
introduced only as explicit opt-in functionality with its trust and security
requirements documented. It must not change the default cross-process contract.

## Consequences

- Queue data remains inspectable, interoperable, and safe to deserialize.
- Django task arguments and return values fit the same JSON boundary required by
  Django's Tasks framework.
- Arbitrary Python objects must be normalized by callers before enqueueing.
- Queue implementations need durable item metadata by ID in addition to their
  pending-item data structure if they offer lookup after dispatch.
- The schema can later gain worker identity, attempt counters, and delivery
  lease metadata without changing payload encoding.
